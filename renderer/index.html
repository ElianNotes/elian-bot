How ElianBot works

The idea

One job = one .sh file on disk, run by plain code — on a cron schedule or on click. AI (Grok) writes the script once; ElianBot runs it forever, free and deterministic. The app must be open for anything to fire.

Jobs

A job is a Name, a Description (a read-only record of the prompt that created it — Grok fills this over MCP; it is never executed and has no effect on runs), and a script — only the script runs. The Repeat dropdowns build the schedule for you (every X minutes / hourly / daily / weekdays / weekly / monthly at a time); the cron field underneath is for power users and always shows the result, with a plain-words preview and the next fire time. The 📁 icon reveals the .sh on disk. Per job: Run now · Pause · Edit · Delete. Delete never touches the script file.

Webhook panel — push output to another app

In a job's WEBHOOK panel paste a URL and (optionally) an Authorization value — e.g. from a GrokBot routine: "POST to" goes in the URL field, the "key" goes in the masked field (any paste shape works: bare key, Bearer x, or the full header line). Every successful run then POSTs {source, job, at, output} there. The secret is written straight into secrets.json on this Mac — it can never be read back from the UI, and the feed only ever shows auth=stored.

Talking with @ — lines a script prints

@grok <text>posts to the feed — Grok reads it with read_messages
@<job-slug>runs that job with this output as its input (chains cap at depth 3)
@notify <text>macOS notification, immediately
@webhook <url>POSTs {job, at, note, output} as JSON to any app
@webhook <url> auth=<name>same, plus Authorization: Bearer <token> — the token is read from secrets.json in the data folder under <name>. Put keys there by hand; they never appear in output, the feed, or this chat

The slug is the job name lowercased with dashes: “Daily Brief” → @daily-brief. Only lines that start with @ count, and job→job mentions fire only from successful runs.

What a script receives

$ELIANBOT_INPUTtext handed over by a mention or run_job (first 8 KB)
$ELIANBOT_INPUT_FILEpath to the full input
$ELIANBOT_JOB_NAME / $ELIANBOT_JOB_IDwho am I
$ELIANBOT_LOGpath of this run's log file

Auto-ping

Every finished run posts a quiet ping to the feed (success/fail, duration) and fires a macOS notification — failures with sound. Grok sees pings via read_messages; it cannot be woken up, it reads when it next looks.

Grok's remote control (MCP)

list_jobs · get_job · create_job · update_job · run_job · pause_job · resume_job · get_output · read_messages · send_message · delete_job. Grok sets each job's name, description (your original prompt), script, schedule, and webhook URL — but never touches secrets. The MCP only edits data files; the open app is the only thing that runs jobs.

Dashboard & data

The Dashboard tab: calendar of past runs (green ok, red failed, blue scheduled), click a day for its timeline, click a run for its log; the message feed lives below. The green tab in the header is the data folder — click it to move everything elsewhere (jobs, logs, scripts move along; the choice is remembered).
